# <span style="background:linear-gradient(90deg,#4f46e5,#06b6d4);-webkit-background-clip:text;color:transparent;">这一路走来｜从手写HTML → WordPress Argon → Astro Firefly魔改</span>

> 前言：本篇记录不是一份建站教程，是一段折腾个人站点的心路。如果你正在犹豫要不要搭建自己的博客，或是正在反复推倒重做站点，或许能在这里找到一点共鸣。

## 开篇简述

历时三年有余，三次站点重构。一路产出大量内容，也曾因操作失误，文章几乎全军覆没。恰逢AI技术飞速发展，我也借助AI能力不断打磨、适配这套博客。从手写页面到动态CMS，最终落脚在魔改后的 Astro Firefly。
<br><br>
建站的本质，是不断在<strong style="background:linear-gradient(90deg,#4f46e5,#06b6d4);-webkit-background-clip:text;color:transparent;">性能、颜值、自由度、维护成本</strong>之间寻找平衡点。很多新人建站容易陷入一个误区：先追求华丽特效，最后忽略内容本身。我也是踩过无数坑之后，才慢慢理解这件事。
</p>

## 🧭 为什么一定要拥有一个独立博客？

<div style="padding:18px;border-radius:14px;border:1px solid rgba(6,182,212,0.22);transition:all 0.3s cubic-bezier(0.2,0,0.2,1);margin:12px 0 24px 0;"
onmouseover="this.style.transform='translateY(-3px)';this.style.boxShadow='0 0 12px rgba(6,182,212,0.14)';this.style.borderColor='rgba(6,182,212,0.4)';"
onmouseout="this.style.transform='translateY(0)';this.style.boxShadow='none';this.style.borderColor='rgba(6,182,212,0.22)';">
<p style="margin:0;line-height:1.7;">
平台博客、公众号、掘金、知乎这类平台固然方便，但是内容所有权并不完全属于你。平台规则变动、限流、删帖、账号封禁，多年积累的文字随时可能消失。
<br><br>
独立博客的核心价值，就是<strong>内容主权</strong>。文章以Markdown文本保存在Git仓库，只要源码在手，站点随时可以迁移、重建。不受任何平台的算法、审核规则约束，可以自由记录思考、技术笔记、随笔感悟。当然，自由的代价，就是所有维护工作都需要自己承担。
</p>
</div>

    <h3 style="margin:0 0 8px 0;font-size:1.2rem;">阶段一｜初代 · 手写原生 HTML</h3>
    <p style="margin:0 0 8px 0;"><strong>定位：从零搭建，最朴素的网页</strong></p>
    <p style="line-height:1.7;margin:0 0 10px 0;">
    最早的博客，没有框架、没有后台，每一篇文章都是独立 <code style="padding:2px 6px;border-radius:4px;border:1px solid #cbd5e1;font-size:0.9rem;">.html</code> 文件。CSS内嵌，图片路径硬编码，写完直接上传服务器。
    </p>
    <p>✅ 亮点</p>
    <ul style="margin:4px 0;padding-left:20px;">
    <li>零依赖，页面干净，加载速度极快</li>
    <li>源码完全可控，想改哪里改哪里</li>
    <li>不需要任何构建工具，记事本就能修改页面</li>
    </ul>
    <p>❌ 痛点</p>
    <ul style="margin:4px 0;padding-left:20px;">
    <li>新增文章必须手动修改导航、侧边栏</li>
    <li>全局样式改动，需要逐个修改所有页面</li>
    <li>文章数量增加后，维护成本爆炸</li>
    <li>没有标签、分类、搜索等基础博客功能</li>
    </ul>
    <p style="margin-top:10px;line-height:1.7;">
    这个阶段更像是练手，适合刚入门前端的人。写了十几篇之后，每次新增文章都要复制整份html模板，慢慢感觉到这种方式完全无法长期维护。于是开始寻找成熟博客系统。
    </p>

    <h3 style="margin:0 0 8px 0;font-size:1.2rem;">阶段二｜二代 · WordPress + Argon 主题</h3>
    <p style="margin:0 0 8px 0;"><strong>定位：颜值优先，开箱即用的动态博客</strong></p>
    <p style="line-height:1.7;margin:0 0 10px 0;">
    厌倦手动维护页面，切换到 WordPress，搭配当时一眼看中的 Argon 主题。后台可视化操作，深色模式、头图、配色均可在面板调整，分类、标签、评论、插件生态齐全，写作门槛大幅降低。
    </p>
    <p style="line-height:1.7;margin:0 0 10px 0;">
    那段时间持续输出，积累了不少文章。但一次操作失误，数据库与备份处理不当，苦心写下的内容几乎全军覆没。
    这次重大损失，也让我意识到数据备份的重要性。之后不断浏览各路大佬的博客、翻阅源码，学到大量建站、备份、运维相关的经验。
    </p>
    <p>✅ 亮点</p>
    <ul style="margin:4px 0;padding-left:20px;">
    <li>浏览器后台直接发文，专注内容创作</li>
    <li>Argon 界面精致，自定义选项丰富</li>
    <li>海量插件，统计、美化、评论一键接入</li>
    <li>非技术人员也能快速上手搭建</li>
    </ul>
    <p>❌ 痛点</p>
    <ul style="margin:4px 0;padding-left:20px;">
    <li>PHP+数据库，服务器需要持续维护，安全隐患多</li>
    <li>插件堆砌导致页面臃肿，加载变慢</li>
    <li>数据库备份、站点迁移流程繁琐</li>
    <li>动态站点的沉重感，背离轻量化初衷</li>
    </ul>
    <p style="margin-top:10px;line-height:1.7;">
    WP这套方案我坚持了一年左右。数据库被误清空这件事，是促使我转向静态站点最关键的转折点。动态数据库一旦损坏，恢复难度远大于纯文本Markdown。
    </p>

    <h3 style="margin:0 0 8px 0;font-size:1.2rem;">阶段三｜三代 · Astro + Firefly 主题（深度魔改）</h3>
    <p style="margin:0 0 8px 0;"><strong>定位：性能为王，源码自主掌控</strong></p>
    <p style="line-height:1.7;margin:0 0 10px 0;">
    经历过数据丢失的教训，再加上从各位大佬那里汲取的经验，恰逢AI高速发展，我开始借助AI来协助开发、调试与适配博客，最终转向静态站点。
    </p>
    <p style="line-height:1.7;margin:0 0 10px 0;">
    选择 Firefly 作为基础模板，基于源码大量魔改：调整布局、重写样式、优化交互、删减冗余组件，加入自定义功能。很多组件调试、样式兼容、代码排错、文章润色的工作，都依靠AI辅助完成。
    文章本地使用 Markdown / MDX 撰写，源码存入 Git 仓库，提交代码自动构建部署，无数据库。
    内容以文本源码形式保存，天然支持版本回溯，最大程度规避一次性丢库的风险。
    </p>
    <p>✅ 亮点</p>
    <ul style="margin:4px 0;padding-left:20px;">
    <li>静态文件，访问速度优异，服务器压力极低</li>
    <li>Astro 岛屿架构，按需加载，极致性能</li>
    <li>Markdown写作 + Git版本管理，备份即源码</li>
    <li>魔改主题，借助AI快速完成代码调试与适配</li>
    <li>大量前端难题、样式bug可以借助AI快速定位解决</li>
    </ul>
    <p>❌ 痛点</p>
    <ul style="margin:4px 0;padding-left:20px;">
    <li>需要前端基础，修改组件需要阅读源码</li>
    <li>无可视化后台，新增文章需要本地编写md</li>
    <li>AI只能作为辅助，核心逻辑与设计思路依然需要自己把控</li>
    <li>构建部署流程需要自己维护，CI/CD配置需要调试</li>
    </ul>
    <p style="margin-top:10px;line-height:1.7;">
    这一阶段是我投入时间最多的。不再盲目追求各种炫酷插件，优先保证页面加载速度、可迁移性和数据安全。同时，我也开始在文章里加入内联交互特效，就是你现在看到的悬浮卡片、对话气泡、进度条等。
    </p>

</p>

<p style="margin:0;font-weight:600;">🔴 坑1：忽略备份，数据库清空丢失全部文章</p>
<p style="margin:6px 0 0 0;line-height:1.7;">WordPress时代最惨痛的教训，只依赖服务器快照，没有独立导出备份。一次误操作清空数据库，几年文字直接消失。从那之后养成多端备份习惯：Git+对象存储+本地副本。<br><br><strong>经验：备份不能只做一份，至少异地多副本，并且定期验证备份文件是否可以正常恢复。</strong></p>
</div>

<p style="margin:0;font-weight:600;">🟠 坑2：过度堆砌插件，页面性能雪崩</p>
<p style="margin:6px 0 0 0;line-height:1.7;">WordPress插件越装越多，统计、美化、评论、CDN插件叠加，JS文件数十个，LCP加载时间直接拉满，移动端体验极差。<br><br><strong>经验：能不用插件就不用插件，每增加一个组件，都要评估对页面性能带来的负担。</strong></p>
</div>

<p style="margin:6px 0 0 0;line-height:1.7;">早期直接修改Firefly原始源码，主题更新时大量代码冲突，无法直接拉取新版本。后续改用覆盖文件的方式做自定义，隔离修改，方便后续同步上游更新。<br><br><strong>经验：主题二次开发尽量不要直接改动原始仓库代码，使用覆盖/扩展模式，降低版本升级成本。</strong></p>

## 💡 关于特效与页面美观的思考

<div style="padding:18px;border-radius:14px;border:1px solid rgba(236,72,153,0.22);transition:all 0.3s cubic-bezier(0.2,0,0.2,1);margin:12px 0 24px 0;"
onmouseover="this.style.transform='translateY(-3px)';this.style.boxShadow='0 0 12px rgba(236,72,153,0.14)';this.style.borderColor='rgba(236,72,153,0.4)';"
onmouseout="this.style.transform='translateY(0)';this.style.boxShadow='none';this.style.borderColor='rgba(236,72,153,0.22)';">
<p style="margin:0;line-height:1.7;">
你在这篇文章看到的悬浮卡片、对话气泡、进度条，全部使用内联HTML+原生JS实现。没有引入额外JS库，尽可能控制脚本体积。
<br><br>
我对特效的原则：<strong>特效服务阅读，而不是干扰阅读</strong>。动画要轻柔，不闪烁、不自动播放大幅度动效，暗色模式也要兼容。如果特效会拖慢页面加载，再好看我也会舍弃。很多博客为了视觉炫酷，大量引入动画库，结果页面打开卡顿，本末倒置。
<br><br>
所以我选择这种轻量方案：只在hover触发交互，页面加载无额外开销，同时保留一点点精致感。
</p>
</div>
